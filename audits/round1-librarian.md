1. **Render the source registry as a first-class site route**
   `sources/registry.md` is the canonical mapping every claim depends on, but it is not built. The "Bibliography" card on the home page deep-links to `bibliography.md` on GitHub, while the registry of record sits at `sources/registry.md`; from the live Willis page a researcher cannot resolve `[coachbagrehab-dating]` in any number of clicks without leaving the site to GitHub. Add `src/pages/sources/index.astro` and `src/pages/sources/[id].astro` that render the registry from a content collection, with one stable URL per source ID. **Rationale tag**: Findability.

2. **Hyperlink inline `[source-id]` markers to their registry entries**
   In the rendered Willis page, every inline citation (`[coach-catalogs-1960-1989]`, `[yourgreatfinds-collectors-guide]`, etc.) is plain text. STYLE.md §2 calls these "stable IDs" but the build does not turn them into anchors. Add a remark plugin (or an Astro rehype step) that rewrites `[id]` and `[id1, id2]` patterns into `<a href="/coachbook/sources/{id}/">` links, with hover text showing tier + title. This is the click-1 promise of a citation-disciplined archive: claim → source. **Rationale tag**: Citation.

3. **Add a build-time check that the inline-cite syntax actually parses**
   STYLE.md §8 promises build-time failure on "a `sources` ID not present in the registry," but the inline `[id]` brackets are not currently extracted. Write a content-collection validator that (a) extracts every `[a-z0-9-]+` token inside square brackets in body markdown, (b) confirms each is in `sources/registry.md`, and (c) fails the build on misses. Without this, `[research/E-authentication.md §2]` (which appears in `models/willis.md`) and a real source ID look identical to humans but only one resolves. **Rationale tag**: Citation.

4. **Disambiguate inline `[bracketed]` references: source IDs vs file pointers vs label codes**
   In `models/willis.md` the same syntactic shape `[X]` is used for source IDs (`[coach-catalogs-1960-1989]`), for cross-file pointers (`[research/E-authentication.md §2]` is referenced as plain prose), for label codes inside parens (`(D1)`, `(E1)`, `(E8)`), and for confidence words wrapped in backticks. A reference work needs one citation grammar. Reserve `[id]` for source IDs only; move file pointers to a `See also` block with explicit `→ /research/...` links; either retire or formalize the (D1)/(E1) shorthand in a "Label key" section that resolves on hover. **Rationale tag**: Citation.

5. **Render errata as a navigable page with anchors per entry**
   `errata.md` is 121 entries (`grep -c "^### "`) — substantial enough to be a primary deliverable of the archive's trust posture — but the home page links it as a raw `errata.md` blob on GitHub. Build `src/pages/errata/index.astro` with one anchor per entry (slugged from the date + first six words) so a researcher reading "Cashin tenure marked disputed" on a designer page can deep-link to the exact errata entry that flagged it. Reverse-link from each model/designer page: every `Files: <path>` line in errata becomes a backlink rendered on the affected entry's "Errata" tab. **Rationale tag**: Errata.

6. **Reconcile the confidence-tag enum across STYLE.md, the schema, and the rendered chips**
   STYLE.md §3 enumerates five values (`confirmed | likely | tentative | disputed | mixed`); `src/content/config.ts` adds `log` and `framework`; the home-page chip legend names only four; the rendered Willis page shows `<span class="chip" data-confidence="likely">` but `tentative` has no `data-confidence` attribute (line 97 of `index.astro`: `<span class="chip">tentative</span>`). Pick the canonical seven (`confirmed | likely | tentative | disputed | mixed | log | framework`), document each with its meaning + when-to-use in STYLE.md §3, ensure every chip carries the `data-confidence` attribute, and define a CSS color per value. A confidence vocabulary that varies between three documents is not yet a controlled vocabulary. **Rationale tag**: Vocabulary.

7. **Resolve the era / era_code dual-field problem with a single canonical form**
   `models/willis.md` carries both `era: classic-nyc` and `era_code: E3`; the schema (`src/content/config.ts` lines 39-49) accepts E-codes, named eras, and a permissive `z.string()` fallback. STYLE.md §11.1 documents this as deliberate, but the rendered Willis page displays `Era: classic-nyc` while the cross-cutting authentication matrix is keyed E1–E5. A reader landing on Willis sees `classic-nyc`; a reader filtering authentication by era sees `E3`. Pick one as the display canonical (the named era is friendlier; the E-code is queryable) and render BOTH on every entry's metadata block (`Era: Classic NYC (E3)`), so the named era is human-legible and the E-code anchors cross-cutting joins. Drop the `z.string()` fallback after a normalization pass. **Rationale tag**: Vocabulary.

8. **Audit the registry tier section-header vs `tier:` field mismatch**
   `coach-catalogs-1960-1989` lives under the `## Tier 2 — Reputable secondary` header but its metadata says `- tier: 1`. The same problem affects `uspto-tm-coach-leatherware`, `uspto-patent-turnlock-3201162`, `coach-s1-2000`, `coach-fb-1962-cashin`, and `risd-cashin-1962` — six entries placed under the wrong tier section. A researcher scanning the registry by section will miss these as primary sources. Move each to the correct section, OR (preferably) generate the rendered registry from the `tier:` field rather than from header position. **Rationale tag**: Source-tier.

9. **Capture archive.org snapshots for the 25 sources marked `snapshot: TODO`**
   `grep -c "snapshot: TODO"` in the registry returns 25 — including foundational sources like `fundinguniverse-coach`, `wwd-coach-early-years`, `vintagefashionguild-cashin`, every USPTO entry, and every museum finding aid. STYLE.md §8 says build-time checks fail "on a registry entry without an archive.org snapshot URL," but every published model entry currently passes despite citing snapshot-less sources. Either turn the snapshot field into an actual hard requirement on `tier: 1` and `tier: 2` entries, or add a "snapshot pending" badge to the registry rendering and a dashboard counting the gap. URL rot is the single largest existential risk to a citation archive. **Rationale tag**: Provenance.

10. **Add a `rights:` field to every registry entry and validate it**
    Of ~60 registry entries, only a handful carry `rights:` (5 public-domain + 2 brand). The schema documents `public-domain | fair-use-commentary | brand | community | unknown` but does not enforce presence. A reference site reproducing third-party material (catalog scans under fair use, brand Pinterest images, community photos) needs an unambiguous rights line per source so that any future image pull or quotation can be audited. Make `rights:` required in the registry schema; default unknowns to `unknown` and surface them in a reviewable list. **Rationale tag**: Provenance.

11. **Render the per-claim `facts:` block on entry pages**
    STYLE.md §5 documents a `facts:` array (`{claim, confidence, sources, notes}`) and the schema accepts it (`config.ts` lines 57-66), but `src/pages/models/[slug].astro` ignores it entirely — the model template renders only style numbers, era, intro/disco, designer, closure, confidence, status. The whole point of per-claim citation discipline is that each claim's confidence is visible at the point of reading, not buried in frontmatter. Add a "Facts" section to the model template that renders each fact with its confidence chip and clickable source IDs. **Rationale tag**: Citation.

12. **Backfill `facts:` blocks for every entry that asserts more than one claim**
    `models/willis.md` makes ~12 distinct claims (introduced 1993 fall preview, was best-selling 1996-97, dimensions, closure, hardware, lining, edge treatment, designer in-house, color list, variants, etc.) but ships a single rollup `confidence: likely` and a single `sources:` array. A reader cannot tell which source supports the colors list versus the dimensions versus the discontinuation date without reverse-engineering inline brackets. Make `facts:` mandatory for any model with more than one introduced/discontinued/dimension/designer claim — the rollup tag is no substitute for per-claim provenance. **Rationale tag**: Citation.

13. **Surface frontmatter structured data that is currently invisible**
    `models/willis.md` carries `also_known_as`, `colors_known`, `variants`, `related`, `authentication.expected_serial_patterns`, `authentication.hardware_stamps`, `authentication.common_fakes` — none of these render on the live page. The reader sees prose tables that duplicate the structured data, but cannot machine-read or filter on it (e.g., "show me every model whose `closure: turnlock`"). Either render the structured fields in a sidecar metadata block, or build per-field index pages (`/closures/turnlock/`, `/colors/british-tan/seen-on/`) that lift the structured data into navigable surfaces. **Rationale tag**: Findability.

14. **Add a research-stream index that maps stream codes (D1, E1, M2, P2, …) to source IDs**
    `models/willis.md` cites `(D1)`, `(D9)`, `(D11)`, `(E1)`, `(E2)`, `(E6)`, `(E7)`, `(E8)`, `(E9)`, `(E12)` in body prose. The Sources section at the end of the file decodes these informally — `D1 = yourgreatfinds-collectors-guide`, `E1 = coachbagrehab-dating`, etc. — but only on this one page; a reader of `models/court.md` would have to re-derive the mapping. The stream codes are clearly meaningful (research streams D = models, E = authentication, M/N/O/P/Q = catalog deep-reads) but no global glossary exists. Add `/research/index.astro` that lists every stream code with its scope and the source IDs it maps to, and render the codes as hover-tooltips wherever they appear in prose. **Rationale tag**: Reference-mode.

15. **Build a "view source provenance" panel for each fact on each entry**
    A researcher asking "how do you know Willis was launched Fall Preview 1993?" should be able, from the rendered page, to see in three clicks: (1) the claim with its confidence chip, (2) the source IDs that support it with tier badges, (3) the snapshot URL of each source. Today: click 1 reaches the prose claim; click 2 (on the bare `<code>` source ID at the bottom of the page) does nothing because the IDs are not links; click 3 requires going to GitHub `sources/registry.md` and ctrl-F. The three-click promise is broken at click 2. Fix this jointly with recommendations 1, 2, and 11. **Rationale tag**: Audit-trail.

16. **Define a controlled vocabulary for closure types and validate against it**
    `models/willis.md` says `closure: turnlock`; the errata (entry 2026-05-02 "Springlock closure type added") notes that catalogs use "Springlock," "industrial turnlock," "kiss-lock," "magnetic snap," and "zip" as distinct documented types. The schema accepts `closure: z.string().optional()` (config.ts line 128). Lock down a closure enum (`turnlock | springlock | kiss-lock | magnetic-snap | zip | snap | drawstring | hook | toggle`) tied to entries in `authentication/hardware.md`, with each model's `closure:` linking to that entry. Same treatment needed for `hardware:`, `strap:`, and `leather:` (currently free-text). **Rationale tag**: Vocabulary.

17. **Make every "high-folklore zone" warning programmatically enforceable**
    STYLE.md §4 lists ten folklore-trap topics (Cashin attribution, Manhattan Leather Bags misnomer, single-digit-year ambiguity, etc.) where claims must be `tentative` by default. None of this is checked at build time. Add a folklore-zone validator: any model entry with `designer: bonnie-cashin` AND `introduced > 1974` must carry `designer_confidence: disputed` and a primary citation, or the build fails. Same pattern for "Manhattan Leather Bags" appearing in any prose without being inside quotation marks. The folklore traps are the single most valuable institutional knowledge in this project; encode them as tests, not just prose guidance. **Rationale tag**: Audit-trail.

18. **Normalize the schema's back-compatibility aliases via a migration pass, not indefinite tolerance**
    `config.ts` accepts `tenure_start` AND `coach_tenure_start`, `era_coverage` AND `covers_eras`, `name` AND `title`, `dimensions_in.{w,h,d}` AND `dimensions_in.{width,height,depth}`. STYLE.md §11 frames each as a deliberate decision, but two-name fields are how schemas drift permanently. Run a one-time migration to the canonical names (the un-prefixed, longer-spelling forms) and remove the alias arms from the schema. Two valid spellings of the same field is a mild form of folklore — the same kind of trap STYLE.md §4 warns against in the data itself. **Rationale tag**: Vocabulary.

19. **Add an "evidence summary" tier-roll-up to every model entry**
    A reader of `models/willis.md` cannot at a glance answer: "of the 9 sources in the rollup, how many are Tier 1, 2, 3, 4?" The footer renders source IDs as bare `<code>` tokens. Add a small evidence-tier histogram to the metadata block: `Sources: 1 Tier-1, 0 Tier-2, 7 Tier-3, 1 Tier-4`. The same number rolled up across the site (e.g., "Models entries supported by ≥1 Tier-1 source: 23 / 96") becomes the archive's headline trust metric. Without it, the Tier 1–4 system exists for editors only, not readers. **Rationale tag**: Source-tier.

20. **Provide a stable JSON or RSS feed of errata so external citers can detect retractions**
    Academic-quality reference works publish errata in a machine-readable form so downstream citers can be notified when a claim they relied on has been corrected. `errata.md` has 121 entries with structured Date/Files/Was/Now/Source headers; this is one parser away from a `/errata/feed.xml` (Atom or JSON Feed) where each correction is an entry with a stable URL and a `<related>` link to the affected page. Pair this with a versioned permalink scheme on every claim so a citer's link to "Willis introduced 1980" can be detected by the feed reader once the archive corrects it to 1993. **Rationale tag**: Errata.

21. **Add a `permissions.md` companion to the registry, currently referenced but absent**
    STYLE.md §6 says: "Mirror only with explicit permission, recorded in `sources/permissions.md`." That file does not exist (`ls sources/` shows only `primary/` and `registry.md`). The archive currently mirrors at least one local-copy source (`coach-catalogs-1960-1989` Google Drive folder, `local: /Users/pjdoland/...`) under fair-use-commentary framing, but the permissions trail for that mirror is undocumented. Create `sources/permissions.md` with one entry per mirrored item: who granted permission, on what date, by what mechanism, scope of use. A reference site cannot defend its reproductions without a permissions log. **Rationale tag**: Provenance.
